# Validation status

This document distinguishes checks completed for the local EdgePanel 0.8.4 build from release checks that remain open. The app targets Apple Silicon and macOS 14+, but the available development Mac runs macOS 26.6.2. A build on that Mac does not establish macOS 14 compatibility.

## Completed locally

- `swift test --disable-sandbox --scratch-path .build`: 17 tests passed. They cover dashboard keyboard-focus eligibility, display-coordinate clamping, settings persistence, page navigation boundaries and direction, global shortcut conflict detection, live layout previews, Action Deck button persistence and square-grid geometry, background-image sizing and alignment, widget settings including clocks in other time zones, Pixel Clock and Pixel Dashboard offscreen rendering, timer state, DDC target selection and parsing, and safe `.icuewidget` import.
- Control–Shift–Up/Down commands remain in the app's Page menu. The app now registers global page hotkeys, falling back to Control–Option–Up/Down if macOS reserves the requested combination. On this Mac, the system preferences enable Control–Shift–Up/Down as system shortcuts, and both fallback registrations returned success. Computer-driven key presses did not reach the global hotkey handler; physical keyboard dispatch and animation still require a live check.
- `./scripts/build-app.sh` completed for arm64. The app's Info.plist passed `plutil -lint`, and both the local build and installed app passed strict code-signature verification. The current installed build uses an existing Apple Development identity; it is not a Developer ID release.
- A prior installed build kept the editor alive through a close-and-reopen cycle after a crash had been traced to sending an action to a released editor window. The app now owns that window through an `NSWindowController` with `isReleasedWhenClosed = false`.
- The XENEON video display and its `wch.cn` USB HID touch controller enumerate on the development Mac. The saved display selection resolves to the Corsair display, and the touch mapping test confines synthetic coordinates to that display's bounds.
- The selected XENEON answered DDC/CI luminance reads and writes through the bundled helper. A test changed 80 to 70 and restored 80. The final UI sends a write only after **Apply**; its value and target have been inspected in the local app.
- The editor and dashboard were captured at the XENEON's 2560 × 720 layout. Native clock, performance cards, Pixel Clock, Pixel Dashboard, independent page backgrounds, and a full-width imported timer rendered. A synthetic editor drag updated the panel during movement and persisted after release.
- The refreshed editor navigation, responsive 16:4 preview, inspector card, and compact dashboard header compile and pass the existing 13 tests. The revised layout has not yet been visually checked in a live app window.
- Application widgets now default to 2 × 2 cells and render only the app icon and its name, with no widget card or heading. Compilation and automated tests pass; a screenshot of this revised layout has not yet been captured.
- The app menu now includes Cut, Copy, Paste, and Select All, and the Web URL field has a direct **Paste URL** button. Automated tests compile this change; keyboard and button paste still require an interactive editor check.
- The borderless dashboard window now accepts keyboard focus, its Web view accepts the first click while the editor is active, web form decorations no longer intercept clicks, and a redirected Web widget no longer reloads its original URL on unrelated SwiftUI updates. The focus and first-click properties are covered by an automated test; typing into a live login form still needs an interactive check.
- Clock and Pixel Clock now share a searchable time-zone picker with all identifiers supplied by macOS. Native clock hour, date, and seconds use the selected zone; automated tests cover cross-date-zone output and persistence. The picker still needs a live editor interaction check.
- Pixel Clock was rendered offscreen at 1552 × 420 in calendar, time-and-week, and time-only layouts and visually compared with the supplied reference captures. The calendar day is now cut out of the solid white body; a test checks the negative-space mask. Its new settings and drawing still need a live XENEON/editor interaction check.
- Pixel Dashboard's text, weather, social, water, animation, and clock matrices were rendered offscreen at 1536 × 330, and the complete text dashboard at 1536 × 446. The captures were visually checked for grid spacing, centered content, header, and tab navigation. A live XENEON check of the settings drawer, touch actions, and editor preview remains open.
- Native Clock, CPU, memory, network, timer, and Web cards now accept a per-widget background color while retaining the existing gradient as their default. Automated tests cover color parsing, light/dark contrast selection, persistence, and isolation from adjacent widgets; the color picker and card appearance still need a live visual check.
- A local `.icuewidget` package imported successfully. Tests reject unsafe ZIP paths and report unsupported dependencies. This does not establish compatibility with every Marketplace widget.
- The Action Deck builds with application, URL, Shortcut, recorded key, and page actions. Its configuration round trip is covered by a test. Physical touch activation, keyboard injection into other apps, and imported button images still need an interactive check.
- Action Deck buttons now store an optional face color individually. Tests confirm color persistence and that older saved buttons without the new field still decode with the automatic palette. The picker and key trim still need a live visual check.
- The Action Deck now offers mini (2 × 2 cells), compact (4 × 2 cells), and full-page presets. A test verifies that mini and compact decks fit beside the initial widgets without creating another page. The grid no longer uses a two-axis scroll view; layout tests cover an embedded 400 × 180 deck and a crowded 180 × 120 deck. Prior offscreen SwiftUI renders at 1280 × 360 and 320 × 180 were inspected for square keys and readable icons; the revised layout still needs a live visual check.
- Page backgrounds now accept imported images, including behind the transparent Action Deck grid. The test checks fill, contain, stretch, original size, alignment, and page-setting persistence. Interactive image selection and rendering on the XENEON still need a visual check.
- Sparkle 2.10.0 resolves from Swift Package Manager. The local app embeds the framework, links through its in-bundle runtime path, and passes recursive strict code-signature verification. The app menu includes a manual update action; its live behavior still needs a published feed and a prior installed release.

## Still requiring physical or release validation

- The installed app currently lacks **Input Monitoring** permission. IORegistry shows that the touch device is not seized, and the editor reports that macOS still handles touch. This explains why touches can land on the focused display. The app checks this grant before attempting capture and presents a direct Settings action. Touch redirection after granting the permission has **not** been verified.
- Test taps at the center and corners, press/drag/release, rotation, scaled resolutions, disconnect during drag, sleep/wake, permission revocation, and a competing touch driver. See [HARDWARE_TESTS.md](HARDWARE_TESTS.md).
- Verify that the dashboard covers the entire XENEON menu-bar area while the menu-bar icon remains visible on the main display.
- Install a Developer ID signed and notarized DMG on a separate Apple Silicon Mac running macOS 14. Check Gatekeeper, permission persistence, touch, DDC brightness, and widget import there. The release script has not been run with signing credentials.
- Publish a signed DMG and appcast on GitHub, then test an actual Sparkle upgrade from the previous installed release. The development Mac has no Developer ID signing identity, so this path is not yet validated.
- Local builds now require a stable signing identity unless `EDGE_ALLOW_ADHOC_SIGN=1` is set. Two differently compiled builds signed with the same existing Apple Development identity had matching designated requirements, and the second was installed. Input Monitoring and Accessibility persistence still needs a user-granted, live check.

No claim of complete touch routing or public-release readiness is made from the automated tests alone.
